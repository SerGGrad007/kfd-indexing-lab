## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

[[Ссылка на реализацию]](src/main/kotlin/lab2/ProductSelection.kt)

**Как работает функция и почему выбран такой способ обработки данных?**

Первым делом функция за O(n) обрабатывает продукты в массиве products и с помощью метода associateBy создаёт хэшмэп с поиском по ключу id. 
Это сделано для того, чтобы в дальнейшем поиск конкретного продукта осуществлялся не за O(n), а за O(1). Далее, по схожей причине, из массива excludedIds создаётся
хэшсет для быстрого поиска исключённых товаров (за O(1) понять, стоит ли нам рассматривать товар или пропустить). Также создаются массивы seen, чтобы вести учёт уже 
рассмотренных товаров, и result, для формирования ответа.

Циклом for мы проходимся по массиву recommendedIds; если id присутствует в исключенных - пропускаем; ищем продукт по id в каталоге - если нет, то объект становится null и мы его 
пропускаем через ?: continue. Если продукт доступен и ранее мы его не добавляли в seen (при исполнении операции seen.add(id) вернёт true если элемент новый для HashSet), то 
добавляем в итоговый массив result. Функция возращает именного после выхода из цикла

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Так как мы вообще не изменяем массив recommendedIds, то порядок рекомендаций сохраняется при прохождении по нему циклом for.
Уникальность поддерживается с помощью массива seen. Обработка исключённых, недоступных и неизвестных товаров описана выше.


### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях.

**Время выполнения:**

O(p + r + e) - ожидаемая скорость исполнения

O(p): products.associateBy { it.id } проходит каталог один раз и кладёт каждый товар в словарь за ожидаемое O(1);

O(e): excludedIds.toHashSet() проходит исключения один раз;

O(r): for (id in recommendedIds) проход 1 раз; все операции внутри цикла за O(1);

**Дополнительная память:**

Дополнительная память: O(p + e). Индекс каталога занимает O(p), множество исключений O(e), множество уже добавленных id 
и список результата вместе не больше O(min(p, r)), а min(p, r) ≤ p. 
Размер самого результата не больше min(p, r).

Итого: O(p + e + min(p, r))
